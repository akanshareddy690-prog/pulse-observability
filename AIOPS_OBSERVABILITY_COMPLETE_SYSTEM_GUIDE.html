1. What Is Going On Here? (The Core Problem & Concept)

In enterprise environments, companies run hundreds of servers and databases. Traditional monitoring tools (like standard CloudWatch or Datadog agents) collect every raw log and stack trace and transfer them to an external cloud.

The Fatal Security Flaw in Traditional Monitoring:
Raw application logs accidentally contain unhashed passwords, AWS access keys (AKIA...), database query parameters, customer credit cards, and confidential PII. Transferring this raw data outside the company's local network violates data residency laws (GDPR, HIPAA, RBI) and exposes credentials to cloud breach risks.

Our Solution: The Two-Tier Architecture. We decouple data collection from analytics:

  • Tier 1 (Customer On-Premises Local Collector): Runs inside the customer's private network. It collects raw telemetry, scrubs passwords and secrets locally, stores the unredacted logs strictly in a local database that never leaves, and provides an Egress Proof Panel.
  • Tier 2 (Central SaaS Platform): Operates strictly on sanitized metadata (CPU numbers, latency, timestamps). It runs dynamic statistical correlation (AIOps) to eliminate alert noise and suggests human-approved remediations.

4. Code Deep-Dive: What Each Component Executes

1. collector/data_policy.json (The Security Contract)

Defines the strict schema allowed across the network. Contains the allow-list: payload_id, timestamp_utc, tenant_id, pseudonym_source_id, metrics, health_state, and alert_summary. Strictly bans raw logs, database queries, and credentials.

2. collector/collector.py (Tier 1 Customer Collector)
  • store_raw_locally(...): Writes the unredacted telemetry record containing raw passwords directly to the local SQLite table raw_telemetry. This proves raw data stays on-premise.
  • scrub_text(...): Regex engine that scans text and replaces sensitive patterns (AKIAIOSFODNN7EXAMPLE → [REDACTED_AWS_KEY]).
  • transform_and_enforce_policy(...): Pseudonymizes internal hostnames (prod-db-master.corp.internal → srv-node-db01) and discards any field not explicitly on the allow-list.
  • send_to_saas(...): Sends the clean metadata to SaaS over HTTP. If unreachable, it diverts the payload into the SQLite outage_buffer table.
  • flush_outage_buffer(...): Background worker that continuously monitors connectivity and replays queued records in FIFO order upon reconnection.
  • EgressProofHandler: Serves the live Egress Proof Panel web interface on Port 8001.
3. saas/server.py (Tier 2 Central SaaS Platform & AIOps Core)
  • POST /api/v1/telemetry/ingest: Verifies the Bearer token. Checks payload_id against INGESTED_PAYLOAD_IDS; if already processed, acknowledges 200 OK without corrupting metrics. Stores clean metadata in saas_platform.db.
  • calculate_z_score(...): Statistical function calculating Z = (x - mean) / std over a 30-sample rolling window.
  • run_aiops_evaluation(...): Flags anomalies if Z > 2.5. Correlates co-occurring spikes (e.g. CPU + Latency) into a single incident with confidence score and mitigation steps.
  • compute_overall_health(...): Classifies health into 4 states: Excellent, Good, Fair, Poor. Automatically downgrades state if telemetry stops arriving for >30s or collector heartbeat is lost for >60s.
  • POST /api/v1/remediation/approve: Records operator approval of the mitigation action into the remediation_audit table.

5. The End-to-End Lifecycle of a Single Data Packet

Follow the exact journey of one telemetry event through the system:

Step 1: Event Generation (Customer Host)
A database server experiences a CPU spike (91.2%) and elevated round-trip latency (220ms). Its local log records: "DB timeout: auth_token=sk_live_9988223344 on prod-db-master.corp.internal".
Step 2: Local On-Premise Storage (Privacy Guarantee)
The complete raw record with plain secrets is stored into collector_local.db inside the customer VPC. It will never cross the network.
Step 3: Redaction & Policy Enforcement (Local Collector)
The privacy engine scrubs auth_token=[REDACTED_SECRET], masks the hostname to srv-node-db01, extracts numeric metrics, and strictly strips raw stack traces.
Step 4: Egress Proof Logging
The scrubbed payload is recorded in the local Egress Ledger and rendered live on http://localhost:8001 for compliance verification.
Step 5: Encrypted Ingestion & Deduplication (SaaS Platform)
Transmitted to Port 8000 with a unique payload_id. SaaS verifies authentication, checks the deduplication cache, and indexes the event by its UTC timestamp.
Step 6: Statistical Analysis & Incident Correlation (AIOps)
The AIOps engine detects that latency is Z = +3.4σ above baseline and CPU is Z = +2.8σ. Rather than creating 2 separate noisy alerts, it synthesizes them into: "Correlated Incident: Service Congestion & Compute Saturation on srv-node-db01".
Step 7: Operator Action & Audit Trail
The operations engineer reviews the incident on http://localhost:8000, inspects the Why Flagged breakdown, and clicks "Approve Remediation". The incident resolves and an entry is logged in the permanent audit trail.
